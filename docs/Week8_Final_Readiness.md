## Матрица реализации (главные сценарии)
| Требование | UX/Требования | Flutter | Статус |
|---|---|---|---|
| Выбор роли | Да | Локальное переключение | Демо |
| Регистрация / вход | Да | Нет | Не реализовано |
| Приглашение ученика | Да | Нет | Не реализовано |
| Кабинеты ученика/репетитора | Да | Демонстрационные | Демо |
| Расписание | Да | Два фиксированных занятия | Частично |
| Создание / перенос занятия | Да | Нет | Не реализовано |
| Домашнее задание | Да | Фиксированное ДЗ | Частично |
| Сдача и проверка работы | Да | Смена статуса в памяти, заранее заданный отзыв | Демо |
| RBAC, FastAPI, PostgreSQL | Архитектурный проект | Нет | Не реализовано |
| Каталог и верификация | v1.1 | Нет | Не входит в MVP |
| AI / видеосвязь | v2.0 | Нет | Не входит в MVP |

**Ограничение:** Widget-тесты не подтверждают работу сервера, базу данных, передачу файлов и реальные пользовательские аккаунты. Скриншоты состояний «На проверке» / «Проверено» необходимо добавить в отчёт отдельно.

1. Сверить и актуализировать перечень экранов Figma: Week5 в GitHub описывает первоначальные 12 экранов, позднее прототип расширялся.

4. Репетировать демонстрацию 5–7 минут и чётко разделять продуктовую концепцию, интерактивный UX-прототип и Flutter-реализацию.

## Сценарий защиты
1. Проблема разрозненных инструментов и целевая аудитория.
2. BA/PM-процесс: Discovery → процессы → требования → MVP → UX → архитектура.
3. Figma — целевой UX. Flutter — работающий локальный прототип.
4. Показ: выбор роли → ученик → отправка ДЗ → репетитор → проверка → ученик → отзыв.
5. GitHub, `flutter analyze` и `flutter test`.
6. Ограничения, следующие задачи и стратегия релизов.

**Итог:** Основной BA/PM-пакет и frontend-прототип подготовлены. Полноценный production MVP пока не создан.
