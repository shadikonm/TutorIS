# TutorIS — Week 6: System Design
**Период:** 29 ноября – 5 декабря 2026. **Статус:** архитектурный проект v0.1, не готовый код.

## Архитектура (проект)
- **Flutter** (Android/iOS): два интерфейса по ролям student/tutor.
- **FastAPI modular monolith:** бизнес-правила, разграничение доступа, REST API.
- **PostgreSQL:** пользователи, связи «репетитор–ученик», расписание, домашние задания, ответы и проверки.
- **OIDC identity provider:** внешний сервис авторизации ещё не выбран.
- **Private object storage:** файлы домашних работ хранятся отдельно; короткоживущие подписанные ссылки.
- **Notifications/outbox:** уведомления об изменениях занятий и статусах работ.

## Сущности ER-модели (13)
`users`, `tutor_profiles`, `student_profiles`, `invitations`, `tutor_student_links`, `lessons`, `homework_assignments`, `homework_submissions`, `submission_files`, `homework_reviews`, `notifications`, `consents`, `audit_events`.

## Критический сквозной сценарий
1. Репетитор публикует домашнее задание, связанное с активной `tutor_student_link`.
2. Ученик отправляет работу через `POST /v1/homework/{assignment_id}/submissions`. API проверяет связь, сохраняет `status=submitted` и `submitted_at`.
3. Репетитор видит работу через `GET /v1/tutor/submissions?status=submitted`, **только** если ученик связан с ним.
4. `GET /v1/submissions/{submission_id}` возвращает детали, а файлы доступны через временные ссылки после проверки доступа.
5. `POST /v1/submissions/{submission_id}/reviews` сохраняет комментарий, меняет статус на `reviewed` или `revision_requested`.
6. Ученик видит статус и отзыв в кабинете.

**Статусы:** `draft → submitted → in_review → reviewed / revision_requested`. При доработке создаётся новая версия ответа.

## RBAC
| Действие | Ученик | Репетитор |
|---|---|---|
| Посмотреть занятия | Только свои | Только свои |
| Создать / перенести занятие | Нет | Для своей учебной пары |
| Создать ДЗ | Нет | Для своей учебной пары |
| Отправить работу | По своему ДЗ | Нет |
| Открыть сданную работу | Свой ответ | Только ответы своих учеников |
| Опубликовать проверку | Нет | Только ответы своих учеников |

## Безопасность и ограничения
- Идентичность берётся из проверенного токена, а не из `student_id` / `tutor_id` в запросе.
- Каждая операция проверяет `tutor_student_links` и права к конкретному объекту.
- Сервер должен отклонять чужие объекты с HTTP 403.
- Файлы приватные; ограничены размер, MIME-тип и срок ссылки.
- Timestamps хранятся в UTC, конфликт занятого времени — HTTP 409.
- Требования к данным несовершеннолетних и согласиям требуют отдельного правового согласования.
