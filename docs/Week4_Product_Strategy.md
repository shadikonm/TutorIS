# Неделя 4. Product Strategy & Planning (15–21 ноября 2026)

**Проект:** TutorIS · **Команда:** один разработчик — @shadikonm · **Версия планирования:** v0.2

## Согласованные решения
1. **MVP** предназначен для репетиторов и **их уже существующих учеников**. Ученик подключается по приглашению/коду. Публичный каталог в MVP не нужен.
2. **Маркетплейс** запускается отдельным релизом **v1.1**.
3. Публикация публичной анкеты требует **верификации**: документальная и предметная проверка, демо-урок, решение модератора; качество дополнительно отслеживается отзывами и жалобами. Для приватного управления существующими учениками публичная верификация не требуется.
4. Приложение планируется на Flutter (Android/iOS); из-за одного исполнителя сначала готовится узкий MVP, а не вся функциональность сразу.
5. До **15 декабря 2026** — BA/PM-пакет, UX-прототип, архитектура и старт приложения, а **не** полностью готовые MVP/v1.1/v2.0.

### Приоритетные цепочки зависимостей
- Авторизация и разграничение доступа → приглашение ученика → занятия → расписание.
- Авторизация → создание ДЗ → отправка работы → проверка и обратная связь.
- Профиль репетитора → заявка на верификацию → тест/документы и демо-урок → решение администратора → публикация каталога → поиск → запрос занятия.
- Видеоурок → интерактивная доска.
- Домашние задания/проверка → AI-подсказки с подтверждением преподавателя.

## MVP — критерии включения в первую версию
1. Регистрация и вход для репетитора/ученика; права доступа и безопасное хранение данных.
2. Приватная связь репетитор–ученик через приглашение.
3. Создание, просмотр, изменение и отмена занятий.
4. Создание, сдача, проверка ДЗ и комментарии.
5. Базовые уведомления и сценарии обработки ошибок.
6. Права доступа проверяются на сервере, а не только в интерфейсе.
7. Приёмочные тесты по основным сценариям; критические дефекты устранены.

**Не входит в MVP:** каталог, публичный поиск, проверка для публикации, платежи, встроенный видеозвонок, AI. На раннем этапе вместо звонков можно использовать внешнюю ссылку.

## RAID
- **Risks:** перечислены выше.
- **Assumptions:** один разработчик; мобильные платформы Android/iOS; сеть доступна для основных операций.
- **Issues:** после технической проверки могут появиться ограничения инфраструктуры; фактические дефекты ещё не зарегистрированы.
- **Dependencies:** Flutter и сервис авторизации, хранилище пользовательских данных, дизайн прототипа и решение о backend-архитектуре.

## Kanban workflow
1. Открыть https://github.com/shadikonm/TutorIS/issues — здесь создано **40 Issues** PB-001…PB-040, назначенных @shadikonm.
2. GitHub → профиль → **Your projects** → **New project** → **Board**.
3. Название: **TutorIS — Product Development**.
4. Создать/настроить статусы **Backlog → To Do → In Progress → Review → Done**.
5. Добавить задачи из репозитория TutorIS через **Add item** / поиск по репозиторию.
6. Сначала переместить в **To Do** 2–3 ближайшие задачи MVP, остальные оставить в **Backlog**.
7. Закрывать Issues только после фактической реализации и проверки критериев приёмки.

**Важно:** GitHub Issues созданы, но GitHub Projects Board ещё нужно создать через UI: доступный интеграционный интерфейс не даёт операции создания Projects.
